# GTT-MEDIA-OLD — архив вышедших публикаций Instagram

Сюда переносится всё, что **уже вышло** в Instagram: Reels, Stories и карусели аккаунтов
@globaltech_tour (Global Tech Tour), @aura_robotics_ru (Aura Robotics) и @ostap.dotsenko (Остап Доценко).
Решение пользователя 29.10.2026: «складывать уже опубликованные рилс и сторис и карусели для инсты, подписывать,
какого числа и в какой из аккаунтов вышел контент, и переносить, а также перенести уже вышедшие ролики».

**Список всех публикаций — [ИНДЕКС.md](ИНДЕКС.md)**: дата, время, аккаунт, формат, тема, ссылка на пост в Instagram
и папка с файлами. Тот же список для программ — `index.json`.

## Как устроено

```
instagram/<аккаунт>/ГГГГ-ММ/ГГГГ-ММ-ДД_ЧЧММ_<формат>_<тема>/
    ролик .mp4 / части Stories 01_…, 02_… / слайды карусели 01.jpg…
    пост.md     — подпись и шапка поста из POST-HUB (кто и когда утвердил)
    info.json   — аккаунт, формат, фактическое время выхода (Москва), ссылка на пост, откуда взято
```

`<формат>` — `reels`, `stories` или `karusel`. Дата и время в имени папки — **фактический выход** по Москве,
по отметке публикатора POST-HUB (может отличаться от плана на минуты).

## Как пополняется

После публикаций агент запускает

```
python3 tools/archive.py --post-hub ../post-hub --video-hub ../VIDEO-HUB
```

Скрипт берёт вышедшие посты из `Ostap-87/POST-HUB` (`<ПРОЕКТ>/INSTAGRAM/<ФОРМАТ>/PUBLISHED/…`), находит файлы
(копии для публикации и мастера роликов в `Ostap-87/VIDEO-HUB`), раскладывает их сюда и обновляет индекс.
Уже перенесённое не трогает. За один заход — до ~900 МБ, дальше коммит, пуш и следующий заход.

- Git LFS здесь **не используется** (бюджет LFS аккаунта исчерпан): все файлы — обычный git, до 100 МБ каждый.
  Ролик больше 95 МБ пережимается (H.264, ~4 Мбит/с — то же качество, что уходит в Instagram).
- Репозиторий публичный: секретов, токенов и персональных данных сюда не кладём.
- Полноразмерные мастера роликов остаются в VIDEO-HUB (`finished-videos/`, Git LFS).
